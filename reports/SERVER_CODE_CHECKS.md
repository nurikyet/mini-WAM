# Проверка нового серверного кода

Это результаты проверки кода. Обучение PPO/NanoWM локально не запускалось.
Серверное обучение, H100/BF16 и итоговый SR ещё не проверены.

Пройдено:

- 15 tests в `tests/test_server_contracts.py` на Python 3.11,
  torch 2.7.1, JAX 0.4.38, numpy 1.26.4; без optimizer steps.
- Компиляция Python-модулей и `bash -n` для серверных скриптов.
- `git diff --check`.
- Проверка SHA256 и чтение настоящего `trivial_1m_v2`: 1 000 000 строк,
  245 996 подходящих строк, 1 890 канонических групп выбранного curriculum.
- Конструкция полных банков основного конфига из настоящего файла для depth=1/2/3:
  по 192 train + 24 val + 48 test. Для каждого состояния перебором проверена
  точная минимальная длина решения.
- Сбор RGB-датасета с тестовой политикой, точный replay каждого перехода,
  проверка действий, масок, SR и diagnostic coordinates. Это проверка формата,
  не обученный эксперт и не результат качества политики.
- Visual task cost на идеальных настоящих будущих кадрах: 264/264 для каждой
  из глубин 1/2/3. Это диагностический oracle-контроль; он не является SR
  обученной NanoWM или доказательством качества её прогнозов.
- Подготовка Git export проверена: vendor/docs/server requirements включаются,
  окружения/кеши/данные/веса/вложенные `.git` исключаются.

Повторить проверки на сервере после `bash scripts/setup_server.sh`:

```bash
.venv-server/bin/python -m unittest discover -s tests -p test_server_contracts.py -v
```

Затем выполнить `bash scripts/train_server.sh smoke` и основной запуск из
[README](../README.md). Старый `VERIFICATION.md` описывает самостоятельный
CNN baseline и не подтверждает качество этого NanoWM-конвейера.
