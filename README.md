# mini-WAM — эксперименты

Текущая постановка: **одна цель, для которой требуется несколько примитивных
переходов**, например пройти три клетки и взять предмет. Прогнозы сравниваем
на **1, 3 и 5 переходов**. Пустой карман и пустые поля инструкции без «!».

План, серверные команды, объём данных и критерии SR:
[исправленная постановка](docs/SINGLE_GOAL_RU.md).
Параллельный запуск девяти моделей на одной H100:
[инструкция](docs/PARALLEL_SERVER_RU.md).
Прежний `one_step` был отладочной задачей возле цели; его результаты не
подтверждают решение новой задачи. Новый SR100 ещё нужно получить на сервере.

Скрипт автоматически сохраняет stdout, stderr и ошибки в отдельный файл каждого
запуска в `logs/`. Одновременно вывод виден в терминале.

```bash
JOBS=3 bash scripts/train_server.sh single-goal-parallel

# Во второй SSH-сессии:
tail -F logs/single-goal-parallel-latest.log
```

PPO, данные и VAE готовятся один раз, после чего до трёх моделей обучаются
одновременно. Результаты этой серии: `runs/server/single_goal_parallel/`;
отдельные логи моделей: `job_logs/` внутри неё. При нехватке памяти повторите
с `JOBS=2`, сохранив код и конфигурацию для продолжения из checkpoints.

`all` и запуск без аргумента теперь запускают `single-goal`.
Это последовательная версия; результаты: `runs/server/single_goal`.
Старые `one-step`, `two-step`, `three-step`
оставлены для воспроизведения прежней постановки.

В логе видны текущая стадия, прогресс и ETA, loss, validation SR, сохранение и
восстановление checkpoints, ошибки с traceback и итоговый код завершения.
Долгие стадии дополнительно печатают периодические сообщения ожидания.
Подробнее о запуске в фоне и чтении логов — в [плане](plan.md#логи-и-наблюдение-за-запуском).

## Посмотреть полученные картинки и видео

Иллюстрация новой среды (настоящий симулятор и эталонные действия, **не результат
обученной модели**): `open runs/previews/single_goal/index.html`.

После параллельной серии скачайте `runs/server/single_goal_parallel/` и передайте
этот каталог в `scripts/view_results.py`. У последовательной версии каталог
называется `single_goal/`. Ниже — просмотр прежних результатов.

После скачивания результатов на Mac:

```bash
python3 scripts/view_results.py --run runs/from-server/one_step
open runs/from-server/one_step/gallery.html
```

Галерея показывает демонстрации PPO, исходные кадры и VAE-реконструкции, реальные
ошибки/успехи политик и пары «настоящий кадр / прогноз». Никакие модели не обучаются.
У старых прогнозов n=1 только один будущий кадр, поэтому соответствующий MP4 статичен.

## Разобрать низкий video SR

Этот раздел относится к старому `one_step`. Новые обучение и проверка:
[одна цель, несколько переходов](docs/SINGLE_GOAL_RU.md).

После переноса обновлённого кода **на сервере**:

```bash
bash scripts/train_server.sh diagnose-video
tail -F logs/diagnose-video-latest.log
```

Это отдельная диагностика на существующем `video/best.pt`, без обучения и без
изменения исходных результатов. Для всех 24 validation-сцен проверяются шесть
действий, настоящие последствия, VAE-реконструкции и прогнозы NanoWM. Сравниваются
старый визуальный критерий и экспериментальный критерий расстояния до публичной
картинки цели в латентном пространстве. Новая картинка цели строится только из
текущего RGB; simulator futures используются исключительно для проверки результата.

Результат: `runs/server/one_step_video_diagnostic/diagnosis.json`, таблицы PNG и
двухкадровые GIF. Код 0 здесь означает, что отчёт создан, а не что достигнут SR100.
Новый критерий не заменяет исходный планировщик до фактической проверки.

Скачать диагностику **в локальном терминале Mac**, затем добавить её в галерею:

```bash
rsync -avh --progress --partial \
  'gangway:~/myproject/mini-WAM/runs/server/one_step_video_diagnostic/' \
  runs/from-server/one_step_video_diagnostic/

python3 scripts/view_results.py --run runs/from-server/one_step \
  --diagnostics runs/from-server/one_step_video_diagnostic
open runs/from-server/one_step/gallery.html
```

Порядок дальнейших действий и ограничения метрик: [разбор video](docs/VIDEO_DIAGNOSIS_RU.md).
